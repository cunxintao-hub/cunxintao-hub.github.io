## 第 1 步 · 核心循环（最关键，多花时间）

**投喂**：`00-总纲与投喂指南.md`、`01-核心循环-钓鱼.md`、`10-交互与异常规则.md`（+ 第 0 步的骨架）

```
你是一位资深 HTML5 网页游戏前端工程师。请帮我实现《疯狂钓鱼佬》的钓鱼核心玩法。

【本轮范围】只实现"钓鱼核心循环"：抛竿 → 咬钩 → 张力判定 → 疯狂收杆 → 结算。
已附上 00-总纲、10-交互与异常规则、01-核心循环-钓鱼，请严格按 01 实现。

【不要做】不要实现装备系统、材料合成、配方合成、等级、钓场、图鉴、工坊、市场、社交等任何其他系统。
不要做装饰性 UI 和华丽动画，本轮只要求功能完整可见。

【硬性约束，违反即返工】
1. 所有数值集中在 config.js，业务代码禁止出现魔法数字（时长、速度、概率、宽度全部走配置）。
2. 状态与渲染分离：state 是唯一数据源，render(state) 只读不写；禁止把状态存在 DOM 上。
3. 每个等待玩家的阶段都必须有超时分支和失败分支，绝对禁止"玩家不操作就永久停留"。
4. 事件统一用 pointerdown，禁止同时绑定 mousedown 和 touchstart。
5. 桌面网页布局：容器最大宽 1280px 居中，最小宽 1024px，窗口更小时整体等比缩放，禁止横向滚动条；
   采用「顶栏 + 左侧栏 260px + 主舞台自适应 + 右侧栏 300px + 底部导航」三栏结构；
   场景区高度 ≥420px，主操作按钮 ≥56px，判定条宽度 ≥520px；
   所有可点元素必须有 hover 态与 cursor:pointer；支持键盘：空格=主操作，Esc=关闭面板。
6. 任何玩家操作都必须有可见反馈（成功、失败、超时都要有明确文案）。

【四阶段具体要求】
1. 抛竿等待：点"🎣 抛竿！"后随机等待 2500~6000ms，显示"抛竿中...等待鱼儿上钩"。
2. 咬钩：显示"❗ 有鱼咬钩了！快点击！"，3000ms 内点击场景任意位置；
   超时提示"😢 反应太慢，鱼跑了..."并可重抛，不计消耗。
3. 张力判定（手感核心）：横向进度条 + 绿色安全区 + 红色指针，指针以 105%/秒 往复移动；
   点"🎯 拉！"时判定指针是否在绿区内，立即反馈"✅ 命中！"或"❌ 未命中"；
   共 3 或 4 轮（随机），每轮绿区位置与宽度重新随机（宽度占条 20%~28%）；
   命中数达 75% 进入收杆，否则提示"😢 拉力失败，鱼挣脱了..."并显示命中明细；
   本阶段必须有 10 秒超时自动失败、剩余时间提示、"放弃"按钮。
4. 疯狂收杆：显示"🔥 疯狂收杆！"+ 进度百分比 + 倒计时，5 秒内每次点击进度 +3.5%，
   达 100% 成功，超时失败并显示最终进度。
5. 结算：弹出鱼获卡片（鱼名、稀有度星级、重量、一句话描述），
   三个操作：收入背包 / 放入图鉴（不可出售）/ 立即售卖（按公式结算金币）；
   结算后累加经验与统计，并保存存档。

【鱼的数据】先用 7 种：鲫鱼、鲤鱼、黑鱼（稀有）、鲶鱼、鳜鱼、鳑鲏、黄颡鱼，
各有稀有度、重量区间、一句话描述，按稀有度权重随机掉落。

【完成后自检，逐条汇报是否满足 + 如何验证】
1. 成功路径能完整钓上一条鱼；
2. 四条失败路径（咬钩超时、张力未达标、收杆超时、无鱼）都能触达且文案明确；
3. 张力阶段放着不操作，10 秒后自动失败，不会永久卡住；
4. 改 config 里的指针速度或绿区宽度，游戏中立刻能观察到变化；
5. 桌面 1440×900 下三栏布局正常，缩到 1024px 无横向滚动条，按钮有 hover 态，空格键能触发主操作；
6. 界面上没有 undefined / NaN / 占位符残留；
7. 连续快速点击不会导致状态错乱。
```
