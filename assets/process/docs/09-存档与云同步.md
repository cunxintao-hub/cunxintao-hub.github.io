# 09 · 存档与云同步（第 2 轮，结构先行）

> 依赖：00｜被依赖：全部模块（所有模块只通过本模块读写持久化数据）

## 1. 模块职责
唯一数据源 `state` 的定义、本地持久化、版本迁移、云同步与冲突处理。

## 3. 本地存储

- key：`fishing_game_save`
- 写入时机：**每次资产变化** + 每 30 秒自动保存 + `visibilitychange` 隐藏时 + `beforeunload`
- 读取时机：页面初始化；解析失败 → 使用默认 `state` 并 toast「存档异常，已新建进度」
- 存储前 `JSON.stringify`，读取后 `mergeDeep(defaults, loaded)` 补全缺失字段

## 4. 版本迁移（强制）

```js
const MIGRATIONS = {
  1: (s) => { /* 未来版本升级逻辑 */ return s; }
};
function migrate(saved) {
  let v = saved.version || 0;
  while (v < CURRENT_VERSION) { saved = MIGRATIONS[++v](saved); saved.version = v; }
  return saved;
}
```
**禁止因为字段缺失导致白屏；任何异常都回退到默认存档。**

## 5. 云同步（可选，接入 CloudBase 时）

- 本地为主、云端为辅；登录后拉取云端存档
- 冲突策略：比较 `level` → `exp` → `stats.totalFishCaught`，取更高者；记录 `lastSyncAt`
- 同步失败：**静默降级**，本地继续可玩，设置页显示「上次同步失败」
- 节流：最短间隔 10 秒，避免频繁写库

## 6. 设置面板

| 项 | 行为 |
|---|---|
| 🔊 音效 | 开关，持久化 |
| 💾 保存进度 | 立即写本地 + 触发云同步 |
| 📂 读取进度 | 从云端拉取（二次确认会覆盖本地） |
| 🗑️ 重置游戏 | 二次确认 → 清空存档 → 回到注册流程 |
| 📖 重置教程 | 清除引导记录，重看新手引导 |

## 7. 失败与反馈

| 场景 | 表现 |
|---|---|
| 存档损坏 | toast + 新建进度（不白屏） |
| 存储空间不足 | toast「存储空间不足，请清理浏览器缓存」 |
| 云同步失败 | 静默降级 + 设置页显示状态 |
| 版本不兼容 | 走迁移；迁移失败则用默认档并提示 |

## 8. 边界（不要做）
- 不在业务模块里直接调 `localStorage`（统一走 `save()/load()`）
- 不做多账号切换
- 不做存档导出/导入文件（后续可选）
