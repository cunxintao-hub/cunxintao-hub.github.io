# 🎣 疯狂钓鱼佬 · 代码骨架（第 0 轮）

PC 浏览器网页游戏，原生 JavaScript + DOM/CSS 渲染，无框架、无构建、无 canvas。
**本轮只交付骨架：所有玩法函数为空实现，只有结构、数值表、布局与存档链路。**

## 运行

```bash
# 方式 A（推荐，localStorage 最稳定）
cd crazy-fisher && python -m http.server 5173
# 打开 http://localhost:5173

# 方式 B：直接双击 index.html（已用 classic script，file:// 可加载；
# 个别浏览器会禁用 file:// 的 localStorage，此时不报错但不落档）
```

## 本轮已落实的约束

- **布局（00 §1.2 / 10 §6）**：容器 `width:min(1280px,100vw)`、`min-width:1024px` 居中；
  窗口 < 1024px 时 JS 按 `scale = innerWidth/1024` 整体缩放并同步抬高容器高度，
  `#viewport` 与 `body` 均 `overflow:hidden`，**无横向滚动条**；主舞台 `min-height:420px`，
  侧栏内部滚动；主操作按钮 56px，普通按钮 40px，间距 8px。
- **可点反馈**：`.clickable/.btn/.list-item/.slot/.nav-item/.icon-btn` 全部
  `cursor:pointer` + hover 提亮/投影 + `:active` 缩放 0.96；连点区 `user-select:none`。
- **事件**：统一 `pointerdown`，未双绑 mousedown/touchstart。
- **键盘**：`空格`=主操作、`Esc`=关闭面板、`Enter`=确认（输入框内不拦截）。
- **数值集中**：所有数值只在 `src/config.js`，业务代码无魔法数字。
- **存档（09）**：key `fishing_game_save`；`load()` 解析失败→默认档 + toast；
  `mergeDeep` 做类型一致校验；`migrate()` 有 MIGRATIONS 与死循环保护；
  30s 自动保存 + `visibilitychange` + `beforeunload`；迁移/写入失败均不白屏。
- **可观测性**：`window.__state` 指向 state，各模块关键节点 `console.log('[模块] ...')`，
  `window.addEventListener('error')` 兜底 toast 并回到安全态。

## 关于模块加载方式

00 §5 要求 ES Modules，同时要求「无构建也能跑、`index.html` 可直接打开」。
`file://` 下 ES Module 会被 CORS 拦截，因此本轮采用 **classic script + `window.FG` 命名空间**
（每个文件一个 IIFE，末尾注册到 `FG`）。文件划分与依赖顺序与 ES Module 完全一致，
后续接 Vite 时只需把各文件的 IIFE 收尾改成 `export`、入口改成 `import` 即可，业务代码不用动。

## 第 4 轮（人物动画 · Lottie）

六个动作随钓鱼阶段自动切换：`抛竿 cast → 等待 wait → 咬钩 bite → 张力 tension → 收杆 reel → 结算 win`。

- **素材分离**（`python tools` 一次性处理，见下）：从 `assets/scene/river.png` 自动抠出
  `assets/actor/boy.png`（人物，轴心=髋部）与 `assets/actor/rod.png`（竿+线+漂，轴心=握把），
  并把竿线漂从底图 inpaint 掉得到 `assets/scene/river_clean.png`（动画底图）。
- **动画数据**：`node tools/build-actor-anim.js` → `assets/actor/actor-data.js`
  （Lottie 合成空间 = 原图 1376×768，因此与 `background-size:cover` 的底图像素级对齐；
  图片内嵌 base64，`file://` 下无 XHR 可直接播放）。
- **播放器**：`src/ui/animator.js` —— 读 `CONFIG.actor.actions` 的「阶段 → 动作 + 是否循环」，
  一次性动作播完按 `after` 自动接循环动作（并有定时器兜底，防 complete 事件不触发时卡住）。
  动画层 `pointer-events:none`，绝不吃点击；`lottie`/数据缺失时自动降级为静态原图，玩法不受影响。
- **依赖**：`vendor/lottie.min.js`（305KB）+ `assets/actor/actor-data.js`（258KB），全本地文件。

局限（重要）：源图是一张**已合成好的扁平插画**，所以只能拆出「人物」「竿线漂」两层，
动作是这两层的**变换补间**（旋转/位移/缩放），不是真正的骨骼绑定；幅度刻意控制在 ±5° / ±10px，
再大就会露出裁切边（人物下半身背后是码头木板）。要真骨骼动画或逐帧动作，需要美术出
分层/绑定源文件（Spine 工程或序列帧）。

### 本轮玩法调整（按反馈）

- **合成台自动随机生成**：每 `merge.autoSpawn.intervalMs = 10000ms`（10 秒）自动生成 1 个材料，
  等级权重 `[88, 9.5, 2, 0.5]`（Lv1~Lv4）——基础材料为主，小概率出现合成材料；
  落点由 `merge.randomPlacement`（默认 true）控制：从**所有空位里随机选一格**，而不是按格子顺序填空
  （挖掘/采集的产出同样走随机落点）；
- **📦 一键收获 = 只收已合成过的材料（Lv.2+）**：每条链 4 级，
  Lv.1 原始 →（1 次二合）→ **Lv.2 可收** →（2 次二合）→ **Lv.3 可收** →（3 次二合）→ **Lv.4 可收**。
  判定走 `level >= merge.harvest.minLevel`（默认 **2**），够等级的格子右下角有 📦 金边角标；
  **Lv.1 原始材料留在台上先合成一次**。没有够等级的材料时提示
  「暂无可收集的物品——需要 Lv.2 以上的材料（先二合 1 次）」。
  背包材料由 04 配方合成直接扣用（`countOwned = 合成台 + 背包`，先扣台面再扣背包）；
- **🎒 背包浮层**（`ui/bag.js`）：左栏不再常驻材料列表，点顶栏 🎒 或快捷栏「背包」打开，
  四页签 `🐟 鱼类 / 🧱 材料 / 🎣 钓具 / 📦 制品`，只读 `state.bag`：
  材料卡 = 来源标签（自然/加工/饵料，`CONFIG.materialTag` + 等级推导）+ 图标 + **中文名** + `×数量`，
  按 `自然→加工→饵料` 排序；钓具卡标「已装备·槽位」；制品页给工坊解锁引导；页签切换原地换内容不关弹窗；
- **体力回复 10 分钟 1 点**：`charges.regenIntervalMs = 600000`（原 30 分钟），上限 8/8，
  不足 10 分钟不回复；挖掘/采集仍各扣 1 点体力；
- **🔋 补充探索次数**（`ui/explorePanel.js`）：合成台操作区入口 → 中央浮层，
  两行（挖掘/采集）各带 `+3 🪙15`、`满充 🪙20`；面板顶部文案的恢复间隔读 config，不改配置自动同步；
  购买走 `systems/merge.buyCharges(type, mode)`——金币与次数成对变更、失败回滚、`throttleLead` 防连点重复扣金币；
  已满 / 金币不足 / 剩余不足 3 次 三种情况都有明确文案并把按钮置灰；
  页面隐藏时不空转，网格满时暂停并只提示一次（合并/清空后自动恢复）。
- **所有基础材料都能合成**：六条链的 `unlockLevel` 与 `chainUnlockAtMergeCount` 本期全部置 0，
  任何 Lv1 材料都能合并升级（等级系统上线后可改回 3/5/5/5 与 [0,0,3,8,15] 恢复门禁）。
- **挖掘/采集改为随机三种 + 一次 3 个**：`merge.source.dig = [矿石, 废料, 黏土]`、

## 🎬 阶段背景视频（钓鱼页）

场景背景从静态插画换成**按阶段切换的循环视频**（`assets/video/`，静音 + `object-fit:cover` 铺满场景，
z-index 0 在所有叠加层之下）。**状态机、按钮、判定、结算逻辑完全不变**，视频纯演出。

| 阶段 | 视频（源文件） | 播放 |
|---|---|---|
| idle 未开始 | `idle.mp4`（0.等待） | 循环 |
| waiting 抛竿 | `cast.mp4`（1.钓鱼） | **只播一次**，播完/2.6s 超时自动接 `wait` |
| biting 等待咬钩 | `wait.mp4`（2.等待） | 循环 |
| tension / reel 拉线 | `fight.mp4`（鱼咬钩拉扯·12.26s） | **原速循环，不强行播完**：结果一出立刻切下一条 |
| caught 成功上鱼 | `success.mp4`（4.上了） | **先播 `catchShowMs`(1.4s) 演出再弹结算卡片**（否则居中卡片立刻盖住视频）；卡片浅色遮罩，视频在背后继续循环 |
| 失败（没鱼/超时/断线） | `fail.mp4`（4.断了） | 演出 2.8s 后自动回阶段视频 |

- **时长拉伸**：`playbackRate = 视频时长 ÷ seconds`，夹在 `videoRateRange [0.35, 1.6]`（`seconds:0` = 原速循环）
- **上鱼演出**：`catchShowMs`(1400ms) 内只放「4.上了」视频 + 🎉 toast，到点再开结算卡片（定时器挂在 `rt.timers`，放弃/结算会一并清掉）
- **结算卡片必须选一个才能继续**：`modal.open({ dismissible:false, light:true })` → 无 ✕、点遮罩不关、`Esc` 也不关
  （收杆是连点操作，遮罩可关就会被连点尾巴"点没"，玩家没选就 auto-settle 进背包）；
  卡片出现后 `catchClickGuardMs`(250ms) 内忽略按钮点击，防连点误选（`main.js` 的 Esc 走 `modal.isDismissible()`）
- **兜底**：视频缺失/解码失败/自动播放被拦 → 移除 `video-on`，自动回退 `assets/scene/{location}.png` 插画或 CSS 渐变，不报错不白屏
- **🆕 双缓冲换片（线上不黑屏）**：场景内两个 `<video>`（`#scene-video` + `#scene-video-b`），
  换片时新片源在另一个里缓冲到 `readyState>=2` 才淡入（0.22s），旧画面一直可见 → `http` 下没有黑屏间隔
  （旧实现直接换 `src`，线上重新下载时会先黑一下；`file://` 本地秒开所以看不出来）
- **🆕 缓冲超时兜底**：`videoSwitchTimeoutMs`(2.5s) 没缓冲出首帧就保留上一画面（或插画/渐变），**绝不切黑屏**
- **🆕 预热**：`preloadAllVideos`（默认开）进入钓鱼页后按顺序静默下载其余阶段视频进缓存；`false` 可关
- **不占后台**：离开钓鱼页 `pauseSceneVideo()` 暂停隐藏并取消未播完的演出（两个播放器都停）；有视频时隐藏 Lottie 人物层避免重影
- 配置在 `CONFIG.fishing.videos`（`{src, seconds, once}`），映射集中在 `render.phaseVideoKey()`；
  调试：`#dev=fishing | bite | reel | catch`（也可靠等待咬钩超时看到 fail 视频）

## 手感微调（钓鱼反应窗口）

玩家反馈偏难，两个「玩家反应窗口」各 **+1 秒**（都在 `config.js → CONFIG.fishing`）：

| 参数 | 基准 | 现在 | 说明 |
|---|---|---|---|
- `biteWindow` 3000 → **4000**（咬钩反应窗口 +1s，再叠加鱼线韧性加成）
- `reelDuration` 5000 → **6000**（疯狂收杆时长 +1s）
- `reelGainPerClick` 3.5 → **5.7**：×力量加成 1.1 = **6.27%/次**，所需点击 **26 → 16 次**
- `requiredHitsRatio` 0.75 → **0.6**：**4 轮只需命中 3 次**（3 轮需 2 次）

还嫌难就继续调：`reelGainPerClick`（每 +1 ≈ 少 2 次点击）、`requiredHitsRatio`、
`cursorSpeed`（0.105 → 0.07 指针变慢）、`targetWidthMin/Max`（0.20/0.28 → 0.30/0.40 绿区变宽）；
